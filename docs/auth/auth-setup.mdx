### 3. **Environment Variables**

Add to `.env.local`:

```bash
# Better Auth (REQUIRED)
BETTER_AUTH_SECRET=your-super-secret-key-min-32-chars-long
BETTER_AUTH_URL=http://localhost:3000

# MongoDB (Already configured)
MONGODB_URI=mongodb://localhost:27017/creator-tracker

# App URLs
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

Generate a secure secret:
```bash
openssl rand -base64 32
```

### 4. **Database Schema**

Better Auth uses these collections in MongoDB:

- **user** - User accounts (id, name, email, emailVerified, image)
- **session** - Active sessions (id, userId, token, expiresAt, ipAddress, userAgent)
- **account** - Auth providers (id, userId, providerId, password)

**Note**: MongoDB doesn't require schema migration. Collections are created automatically.

### 5. **Usage Examples**

#### Server-Side (Server Components & API Routes)

```typescript
import { getSession, requireAuth, requireAdmin } from '@/lib/auth/auth-utils';

// Get current session
const session = await getSession();

// Require authentication
const session = await requireAuth();

// Require admin role
const session = await requireAdmin();

// Check organization access
const hasAccess = await hasOrganizationAccess(userId, orgId);
```

#### Client-Side (Client Components)

```typescript
'use client';
import { useAuth } from '@/hooks/useAuth';
import { authClient } from '@/lib/auth/client';

function MyComponent() {
  const { user, isAuthenticated, isLoading } = useAuth();

  // Sign up
  await authClient.signUp.email({
    email: 'user@example.com',
    password: 'password123',
    name: 'John Doe',
  });

  // Sign in
  await authClient.signIn.email({
    email: 'user@example.com',
    password: 'password123',
  });

  // Sign out
  await authClient.signOut();

  // Change password
  await authClient.changePassword({
    currentPassword: 'old',
    newPassword: 'new',
  });
}
```

### 6. **Protected Routes**

The middleware automatically protects:
- `/dashboard` - Requires authentication
- `/[org]/*` - Organization routes (requires auth)
- `/creator/*` - Creator routes (requires auth)

Auth routes redirect if already signed in:
- `/login` → `/dashboard` (if authenticated)
- `/signup` → `/dashboard` (if authenticated)

### 7. **API Route Pattern**

```typescript
// app/api/posts/route.ts
import { NextResponse } from 'next/server';
import { getSession } from '@/lib/auth/auth-utils';
import connectDB from '@/lib/db/mongodb';

export async function GET() {
  try {
    const session = await getSession();
    
    if (!session) {
      return NextResponse.json(
        { success: false, error: 'Unauthorized' },
        { status: 401 }
      );
    }

    await connectDB();
    // ... your logic

    return NextResponse.json({ success: true, data });
  } catch (error) {
    return NextResponse.json(
      { success: false, error: 'Internal server error' },
      { status: 500 }
    );
  }
}
```

### 8. **User Model Integration**

Better Auth stores core auth data, but our User model has additional fields:

```typescript
// User model extends Better Auth with:
- role: 'admin' | 'creator'
- organizationId: ObjectId
- creatorProfile: { ... }
- preferences: { ... }
```

When a user signs up via Better Auth, you need to sync to your User model:

```typescript
// Create user in your User model after Better Auth signup
import User from '@/lib/db/models/User';

const newUser = await User.create({
  _id: session.user.id,
  email: session.user.email,
  name: session.user.name,
  role: 'creator',
  emailVerified: false,
  loginCount: 0,
  preferences: {
    emailNotifications: true,
    reminderFrequency: 24,
    language: 'en',
  },
});
```

### 11. **Troubleshooting**

**"Session not found" error**:
- Check BETTER_AUTH_SECRET is set
- Clear cookies and try again
- Verify MongoDB connection

**"Unauthorized" on protected routes**:
- Check middleware.ts configuration
- Verify session token cookie exists
- Check browser DevTools → Application → Cookies

**TypeScript errors**:
- Run `bun run type-check`
- Ensure all types are imported correctly
